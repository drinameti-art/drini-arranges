# DriniArranges — own-account Paddle Billing setup

This integration uses the owner's Paddle Billing account directly, **not Lovable Payments**. No real Paddle API or payment has been exercised yet because the owner credentials are not set and the checkout domain is not approved.

## Secure credentials

Add these in **Project Settings → Secrets**, never in chat:

- `PADDLE_API_KEY`: a Paddle Billing server API key from Developer tools → Authentication. Give it products/prices read and write, customers read and write, transactions write, and customer portal sessions write permissions.
- `PADDLE_CLIENT_TOKEN`: a client-side token from the same Paddle account. It is intentionally provided to Paddle.js for checkout; no private API key or webhook secret is sent to the browser.
- `PADDLE_WEBHOOK_SECRET`: the destination-specific signing secret generated by Paddle after creating the notification destination below. Copy directly into Project Settings → Secrets.
- `PADDLE_ENV`: already configured for the owner's live account. The code accepts `production` and `sandbox`; changing environment also requires the matching account's API key, client token and webhook secret. Never mix live and test credentials.

There is no secure secret-request form offered in this agent session; Project Settings → Secrets is the secure entry point. Publish after adding/changing credentials before expecting the published app to use them.

## Catalog and behavior

- The first signed-in checkout prepares both products and stores their IDs in the private environment-scoped `paddle_catalog`. Existing names/custom data and exact matching EUR amounts/intervals are reused, and a database lease serializes first-use setup.
- Pro: **€29.99 every week**, EUR amount `2999`, billing cycle `week/1`, price custom data `{plan: "pro"}`.
- Studio: **€59.99 every month**, EUR amount `5999`, billing cycle `month/1`, price custom data `{plan: "studio"}`.
- Tax category is SaaS; enable this category in the Paddle account if necessary. Tax mode is `account_setting`. Free has no payment product.
- Checkout transactions are created server-side with the verified user's customer and `user_id`. Checkout completion displays a success message and refreshes usage while waiting for the webhook; it never grants a plan itself.
- Signed events update the plan and next billing date. Scheduled cancellation does not remove access early. `past_due` retains access during Paddle's payment recovery; effective `canceled` or `paused` reverts to Free. Configure Paddle's recovery settings to pause/cancel after retries are exhausted.
- Duplicate and stale events are ignored atomically. Canceling an older subscription does not remove another active subscription. Customer/environment ownership must match before any plan update.
- Paid users see **Manage subscription / Menaxho abonimin** in their account menu; the server obtains a fresh Paddle portal session.
- Existing limits are unchanged: Free 3/calendar month, Pro 15/rolling 7 days, Studio 30/calendar month.
